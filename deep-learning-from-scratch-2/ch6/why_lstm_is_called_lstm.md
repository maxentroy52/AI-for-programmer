好问题——名字里的 "Long" 和 "Short-Term" 就藏在 `c` 和 `h` 这两条线里。

## 两条线

LSTM 内部有**两条状态线**，每步都更新：

| 内部量 | 全称 | 角色 |
|---|---|---|
| `h` | hidden state | **短期记忆** |
| `c` | cell state | **长期记忆** |

## Short-Term 体现在 `h`

`h` 是「**短期**」记忆，因为：

```python
h_next = o * tanh(c_next)
```

- `h` 每步都被**重新计算**（覆盖式）。
- 它是对外的**当前输出**，反映「此刻的状态」。
- 下一步如果 `o` 很小，`h` 就几乎为零——**信息很快消失**。
- 它的生命周期就是「当下这几步」。

**这就是 Short-Term**：只在短期内有效，步与步之间会快速变化。

## Long 体现在 `c`

`c` 是「**长期**」记忆，因为：

```python
c_next = f * c_prev + i * g
```

- `c` 是**加法式更新**：旧值保留一部分，加一点新的。
- 只要 `f ≈ 1`，`c` 就**几乎原封不动地传下去**，可以持续几百步。
- 它不像 `h` 那样每步被非线性完全重写，而是**缓慢演化**。

**这就是 Long**：能长期携带信息，不被时间步冲刷掉。

## 关键在于「同一份信息，两种命运」

一个信息进入 LSTM 后：

1. 作为 `g`（候选）被写入 `c`。
2. 如果 `f ≈ 1`，它在 `c` 里**长期存活**（Long）。
3. 但它**不总是出现在输出 `h` 里**——只有 `o` 开大时，`h` 才暴露 `c` 的一部分。
4. 所以 `h` 只是 `c` 的「**当前可见部分**」，是**短期**的。

换句话说：

> **`c` 存的是「长期」，`h` 露的是「短期」。**

## 名字的解读

```
Long     Short-Term     Memory
 │           │             │
 c           h         两者都是
（长期保留） （短期输出）  记忆
```

合起来：

> **Long Short-Term Memory = 能长期（Long）保留的短期（Short-Term）记忆（Memory）**

- 「Short-Term」指信息本身来自序列中的短期上下文（像普通 RNN）。
- 「Long」指这种短期信息现在**能被保留很久**（通过 `c`）。

## 一个例子

假设处理句子：「**猫**坐在垫子上，它很**累**。」

- 读到「猫」时，把「猫」写进 `c`。
- 中间「坐在垫子上」几步，`f ≈ 1`，`c` 里的「猫」**保留**——这是 **Long**。
- 读到「它」时，`o` 开大，`h` 输出「猫」的语义，模型知道「它」指猫——这是 **Short-Term** 的对外使用。

信息在 `c` 里活了很多步（Long），但只在需要时通过 `h` 露出（Short-Term）。

## 对比普通 RNN

普通 RNN 只有 `h` 一条线：

```python
h_t = tanh(...)
```

- 每步覆盖，信息快速消失。
- **没有「Long」的载体**——记不住长期。

LSTM 加了 `c`：

```python
c_t = f * c_{t-1} + i * g
h_t = o * tanh(c_t)
```

- `c` 提供 Long，`h` 提供 Short-Term。
- 两者配合，才有了名字里的 **Long Short-Term**。

## 一句话总结

> **Short-Term 体现在 `h`**：每步重算、快速变化，是当前的短期输出。
> **Long 体现在 `c`**：加法式更新、缓慢演化，能长期保留信息。
> 名字的意思是「**把短期记忆 `h` 延长**」——通过多一条长期线 `c`，让短期信息能长期存活、按需输出。
