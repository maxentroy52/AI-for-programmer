好，用具体数字走一遍。

## 超参数

```
V = 1000    词表大小（1000 个词）
D = 128     词向量维度
H = 32      隐藏状态维度
```

## 两个矩阵

```
embed_W:  (V, D) = (1000, 128)     id → 词向量
affine_W: (H, V) = (32, 1000)      h  → 词表得分
```

## 过一遍单个 token

假设当前 token 是 **id = 42**（词表里的第 42 个词）。

### 1. Embedding：id → 词向量

查 `embed_W` 的第 42 行：

```
embed_W[42] = [0.12, -0.05, 0.33, ..., 0.08]     ← 128 个数
                (D = 128 维)
```

**e: (128,)** —— 这个 token 的 128 维词向量。

### 2. LSTM：词向量 → 隐藏状态

LSTM 读入 `e (128)`，同时带上一步的 `h_prev (32)` 和 `c_prev (32)`，算出一个新的隐藏状态：

```
h: (32,)     ← 32 个数
```

注意：**128 维被 LSTM 压成了 32 维。** D 在这一步「消失」了。

### 3. Affine：隐藏状态 → 词表得分

```
logits = h @ affine_W + b
```

- `h`: `(32,)`
- `affine_W`: `(32, 1000)`
- `b`: `(1000,)`
- `logits`: `(1000,)`

**logits: (1000,)** —— 对 1000 个词各打一个分。

第 v 个词的得分：

```
logits[v] = h[0]*affine_W[0,v] + h[1]*affine_W[1,v] + ... + h[31]*affine_W[31,v] + b[v]
```

即：**32 维的 h，和 affine_W 的第 v 列（32 维）做内积，加偏置。**

## 矩阵形状链

```
id (标量) 
  │ embed_W[42]
e: (128,)          ← D = 128
  │ LSTM
h: (32,)           ← H = 32
  │ affine_W (32, 1000)
logits: (1000,)    ← V = 1000
```

## 数值例子（简化到能看）

为了能算，把维度缩小：`H=3, V=4`（真实是 H=32, V=1000，道理一样）。

```
h = [1, 2, -1]        (H=3)

affine_W = [[ 0.1,  0.2, -0.3,  0.4],    ← 行 0（隐藏维 0）
            [ 0.4, -0.1,  0.5, -0.2],    ← 行 1（隐藏维 1）
            [-0.2,  0.3,  0.1,  0.6]]    ← 行 2（隐藏维 2）
            (3 行, 4 列)

b = [0.5, -0.1, 0.2, 0.0]     (V=4)
```

对每个词打分：

```
logits[0] = h·W[:,0] + b[0] = 1*0.1 + 2*0.4 + (-1)*(-0.2) + 0.5
          = 0.1 + 0.8 + 0.2 + 0.5 = 1.6

logits[1] = h·W[:,1] + b[1] = 1*0.2 + 2*(-0.1) + (-1)*0.3 + (-0.1)
          = 0.2 - 0.2 - 0.3 - 0.1 = -0.4

logits[2] = h·W[:,2] + b[2] = 1*(-0.3) + 2*0.5 + (-1)*0.1 + 0.2
          = -0.3 + 1.0 - 0.1 + 0.2 = 0.8

logits[3] = h·W[:,3] + b[3] = 1*0.4 + 2*(-0.2) + (-1)*0.6 + 0.0
          = 0.4 - 0.4 - 0.6 + 0.0 = -0.6
```

```
logits = [1.6, -0.4, 0.8, -0.6]
```

softmax 后，词 0 概率最高（1.6），词 3 最低（-0.6）。模型认为「下一个词最可能是词 0」。

## 回看 `affine_W` 的 H 和 V

用真实数字 `(32, 1000)`：

```
        列 0    列 1    列 2   ...   列 999
      ┌──────┬──────┬──────┬─────┬──────┐
行 0  │ 0.12 │ 0.03 │ -0.1 │ ... │ 0.22 │  ← 隐藏维第 0 维
行 1  │ -0.4 │ 0.11 │ 0.3  │ ... │ -0.1 │  ← 隐藏维第 1 维
行 2  │ 0.05 │ -0.2 │ 0.15 │ ... │ 0.08 │  ← 隐藏维第 2 维
...   │ ...  │ ...  │ ...  │ ... │ ...  │
行 31 │ 0.3  │ 0.07 │ -0.2 │ ... │ 0.4  │  ← 隐藏维第 31 维
      └──────┴──────┴──────┴─────┴──────┘
        词 0    词 1    词 2        词 999
```

- **每一列** = 一个词的「32 维输出模板」
- **每一行** = 一个隐藏维度对所有词的权重
- **H = 32** → 32 行，因为 `h` 是 32 维
- **V = 1000** → 1000 列，因为要输出 1000 个词的得分

## 对比 `embed_W (1000, 128)`

```
        列 0    列 1   ...   列 127
      ┌──────┬──────┬─────┬──────┐
行 0  │ 0.1  │ -0.2 │ ... │ 0.3  │  ← 词 0 的词向量（128 维）
行 1  │ 0.4  │ 0.1  │ ... │ -0.1 │  ← 词 1 的词向量
行 2  │ -0.1 │ 0.3  │ ... │ 0.2  │  ← 词 2 的词向量
...   │ ...  │ ...  │ ... │ ...  │
行 999│ 0.2  │ -0.1 │ ... │ 0.5  │  ← 词 999 的词向量
      └──────┴──────┴─────┴──────┘
        128 维（D）
```

- **每一行** = 一个词的 128 维词向量
- **V = 1000** → 1000 行（1000 个词）
- **D = 128** → 128 列（词向量维度）

## 两者对比

| | `embed_W` | `affine_W` |
|---|---|---|
| 形状 | `(V, D) = (1000, 128)` | `(H, V) = (32, 1000)` |
| 词在哪 | **行** | **列** |
| 每个词是什么 | 128 维词向量 | 32 维输出模板 |
| 输入维度 | —（查表） | H = 32 |
| 输出维度 | D = 128 | V = 1000 |
| 用途 | id → 向量 | h → 得分 |

## 一句话总结

> `V=1000, D=128, H=32` 时：
> - `embed_W` 是 `(1000, 128)`，**每行一个词**，词 42 的向量是 `embed_W[42]`（128 维）。
> - `affine_W` 是 `(32, 1000)`，**每列一个词**，词 42 的输出模板是 `affine_W[:, 42]`（32 维）。
> - 数据流：`id → e(128) → LSTM → h(32) → Affine → logits(1000)`。
> - `D=128` 在 LSTM 那步变成了 `H=32`，所以 Affine 的输入是 32 维，`affine_W` 是 `(32, 1000)` 而不是 `(128, 1000)`。

## 为什么不能 D ≠ H 时 weight tying

```
embed_W: (1000, 128)
affine_W: (32, 1000)
```

`embed_W.T` 是 `(128, 1000)`，`affine_W` 是 `(32, 1000)`——**行数不同，没法共享**。只有当 `D == H`（比如都设成 128）时，`embed_W.T` 才是 `(128, 1000)`，才能和 `affine_W` 对齐、共享参数。

这就是 weight tying 要求 `D = H` 的原因。
