好问题——这看起来矛盾：既然 `h` 是从 `c` 算出来的，`c` 长期，`h` 怎么反而短期？

关键在于：**`c` 是“仓库”，`h` 是“此刻取出来的那一部分”。仓库可以长期存很多，但每次只取出一点对外用。**

## 先看两个公式

```python
c_t = f * c_{t-1} + i * g        # 长期：加法，缓慢更新
h_t = o * tanh(c_t)              # 短期：门控后的“当前可见部分”
```

## `c` 为什么是长期

- 它是**累加**的：`f * c_prev + ...`，旧值保留一部分，不会每步被完全覆盖。
- 只要 `f ≈ 1`，`c` 可以**原封不动**传几百步。
- 它是一个**持续存在的存储**，像仓库里的货架。

## `h` 为什么是短期

虽然 `h_t` 由 `c_t` 算出，但注意：

**1. `h` 每步都被重新计算，而且是“门控后的部分”**

```python
h_t = o * tanh(c_t)
```

`o` 是输出门（0~1）。如果 `o` 很小，`h_t` 就几乎为零——**不管 `c` 里存了多少，此刻都不对外暴露**。所以 `h` 只反映“这一刻选择展示的东西”，不是 `c` 的全部。

**2. `h` 不参与 `c` 的长期存储**

下一时刻的 `c` 更新：

```python
c_{t+1} = f * c_t + i * g
```

注意：`c` 的更新**只用 `c_t`**，**不用 `h_t`**。`h` 不进入长期存储回路。`h` 是“输出”，不是“存储”。

**3. `h` 是 `c` 的一个“投影/快照”**

`tanh(c_t)` 把 `c` 压到 `-1~1`，再乘 `o`。这一步是**有损的、每步重算的**。它不保留 `c` 的完整信息，只取当前需要展示的部分。

## 类比

把 `c` 想象成**你的全部记忆**（仓库），`h` 想象成**你此刻说出口的话**。

- 记忆（`c`）可以长期保存很多年。
- 但你此刻说的话（`h`）只反映**这一刻你选择说出的那部分记忆**，而且说完就过去了，下一步说别的。
- 话（`h`）是从记忆（`c`）里取的，但**话本身是短期的**——说完就不在了，不会自动变成新的长期记忆。

所以：

| | `c` | `h` |
|---|---|---|
| 角色 | 存储（仓库） | 输出（此刻取出的部分） |
| 更新方式 | 加法，缓慢 | 门控重算，每步变 |
| 是否进入下一步的存储 | **是**（`f * c`） | **否**（`h` 不回流到 `c`） |
| 生命周期 | 长 | 短 |

## 关键点：`h` 不回流到 `c`

这是最容易被忽略的：

```
c_t ──┬──► h_t（输出，短期）
      │
      └──► c_{t+1}（存储，长期）   ← 只用 c_t，不用 h_t
```

`h` 是**旁支输出**，不是主存储线。所以 `h` 短期，不影响 `c` 长期。

## 如果 `h` 也参与 `c` 的更新会怎样

有些变体（比如某些简化 RNN）会写成：

```python
c_t = f * c_prev + i * tanh(W·h_prev + ...)
```

这时 `h_prev` 参与了 `c` 的更新——但**即使这样，`c` 仍然是长期存储，`h` 仍然是短期输出**。因为 `c` 的加法结构保证它能长期保留，而 `h` 只是“当前输入的一部分”。

LSTM 的标准写法里，`c` 的更新用 `h_prev` 参与算门和候选（`A = x@Wx + h_prev@Wh + b`），但 `c` 的**主干**是 `f * c_prev + i * g`，加法结构不变。

## 一句话

> **`c` 是长期存储，`h` 是从 `c` 里“此刻取出来对外展示”的部分。** `h` 由 `c` 算出，但它是**有损的、每步重算的、不回流到存储的**输出——所以短期。`c` 通过加法缓慢累积，所以长期。**“从长期里取出来用”不等于“长期本身”。**

## 再一个类比

- `c` = 你的银行账户余额（长期累积）
- `h` = 你今天取出来花的钱（此刻取出的部分）
- 你今天花的钱是从余额里取的，但**花掉的钱是短期的**，余额（`c`）继续长期存在。

取钱（`h`）不影响余额（`c`）的长期性——因为余额的更新是“存钱 + 利息 - 取钱”的加法，而取钱只是从余额里拿出一部分。
