好问题——看起来确实像冗余，但**那个「最后一个 `h`」和「所有 `hs`」用途完全不同，不是重复。**

## 先看 decoder 里那行

```python
def forward(self, xs, enc_hs):
    h = enc_hs[:, -1]          # ← 取 encoder 最后一步
    self.lstm.set_state(h)     # ← 作为 decoder LSTM 的初始状态
```

**`enc_hs[:, -1]` 是作为 decoder LSTM 的初始状态 `h_0`，不是给 attention 用的。**

## 两个用途，完全不同

| | 所有 `hs` (`enc_hs`) | 最后一个 `h` (`enc_hs[:, -1]`) |
|---|---|---|
| 给谁 | **`TimeAttention`**（每步算权重） | **decoder 的 `TimeLSTM`**（初始状态） |
| 用途 | 每步「看源句的哪部分」 | decoder 从「读完整句的状态」开始生成 |
| 形状 | `(N, S, H)` | `(N, H)` |
| 何时用 | 每个 decoder 时间步 | 只在开头，初始化 LSTM |

**`enc_hs` 是「attention 的查询库」，`enc_hs[:, -1]` 是「decoder 的起点」。** 两者角色不同。

## 为什么 decoder LSTM 需要初始状态

decoder 的 LSTM 是 `stateful=True`，它需要一个**初始 `h_0` 和 `c_0`**。如果不给，就从 0 开始——**但 0 不包含任何源句信息**。

用 `enc_hs[:, -1]` 当初始状态，等于告诉 decoder：

> 「你已经读完了源句，现在是『读完整句』的状态，开始生成吧。」

**这给 decoder 一个「语义起点」**——它从「理解源句」的状态出发，而不是从「空白」出发。

## 如果不用 `enc_hs[:, -1]` 会怎样

```python
# 假设不设初始状态，从 0 开始
self.lstm.set_state(np.zeros((N, H)))
```

- decoder 从「空白」开始生成。
- 虽然 attention 每步还能看 `enc_hs`，**但 LSTM 的初始状态没有源句信息**。
- 生成第一个词时，LSTM 的 `c_0`/`h_0` 是 0，只有 attention 的 `c` 提供源句信息——**信息通路少了一条**。

**用 `enc_hs[:, -1]` 初始化，等于「LSTM 自己也知道源句大意」，和 attention 的「动态看源句」互补。**

## 所以不是冗余，是「两条信息通路」

```
decoder 生成时，源句信息从两条路来：
1. LSTM 初始状态 = enc_hs[:, -1]     ← 静态的「整句大意」
2. Attention 每步的 c                 ← 动态的「聚焦某部分」
```

- **LSTM 初始状态**：给 decoder 一个「全局语义起点」。
- **Attention**：给 decoder 每一步「精细的局部信息」。

**两者互补，不是重复。** 一条是「整句的摘要」（粗），一条是「每步的动态聚焦」（细）。

## 一个类比

你翻译「我爱你」：

- **LSTM 初始状态** = 你读完整句后，脑子里有个「这句话在说爱」的整体印象。
- **Attention** = 你每翻一个词时，回头看一眼原文的对应部分。

**整体印象和逐步查看，是两件事。** 整体印象让你「知道在翻什么」，逐步查看让你「翻得准」。**缺一个都不完整。**

## 一句话

> **不是冗余。`enc_hs[:, -1]` 是给 decoder LSTM 的初始状态（「整句大意」的语义起点），`enc_hs` 是给 attention 的查询库（每步动态聚焦）。** 两者是**两条互补的信息通路**——一条给「全局起点」，一条给「每步细节」。**没有 `enc_hs[:, -1]`，decoder 从空白开始；没有 `enc_hs`，attention 没法聚焦。两者都需要。**

## 顺带：为什么是「最后一个」而不是「平均」或「第一个」

- **最后一个 `h_S`**：LSTM 读完整个源句，`h_S` 包含**全部**源句信息（因为状态累积）。**它是最完整的「整句摘要」。**
- 第一个 `h_1`：只包含第一个词，信息不全。
- 平均：会丢失「顺序」信息。

**`h_S` 是「读完整句」的自然结果，所以用它当初始状态。** 这也是普通 seq2seq 里 `C = h_S` 的同一个东西——attention 保留了它作为「起点」，同时额外提供「所有 `hs`」给 attention。

## 再顺带：这和 peeky 的区别

- **Peeky**：`C = h_S` 拼到**每个时间步的输入**。
- **Attention**：`h_S` 只当**初始状态**，每步的「源句信息」由 attention 动态提供。

**Peeky 是「每步看同一个 `C`」，attention 是「初始状态用 `C`，每步动态看 `hs`」。** attention 更灵活，但**初始状态仍然用 `h_S`**——因为它是个好的「起点」。
