## 需要修正的点

> 「在 `hs` 当中找到与目标词关联最大的**向量**」

**不是「找一个向量」，是「给所有向量算权重，加权求和」。**

```
错误理解:  attention 选中 h_2，只用 h_2
正确理解:  attention 算出权重 [0.1, 0.8, 0.1]，
           context = 0.1*h_1 + 0.8*h_2 + 0.1*h_3
```

**是「软选择」（加权混合），不是「硬选择」（挑一个）。**

为什么用「软」而不是「硬」：

- 硬选择不可导，没法训练。
- 软加权可导，梯度能传回去。
- 而且「混合」比「挑一个」更鲁棒——即使权重不完美，混合也能保留部分信息。

## 完整的 attention 流程（对应你的理解）

```
1. decoder 当前状态 h_t（编码目标上下文）
2. 拿 h_t 和每个 encoder 的 h_s 算「关联分数」  ← 你说的「找关联」
3. 分数 → softmax → 权重 [a_1, ..., a_S]        ← 你说的「重要性程度」
4. context = Σ a_s * h_s                        ← 加权求和（不是挑一个）
5. decoder 用 context + h_t 生成下一个词
```

**你的 2、3 步理解对；第 4 步是「加权求和」，不是「选一个」。**

## 一句话

> **对，encoder 返回所有 `hs` 解决信息溢出；decoder 每步用自己的 `h_t` 去和 `hs` 算关联，得到每个 `h_s` 的重要性权重。** 但 attention **不是「找到关联最大的那个向量」，而是「给所有 `h_s` 算权重，加权求和」**——是「软选择 / 混合」，不是「硬选择 / 挑一个」。这样可导、可训练、更鲁棒。

## 顺带：为什么「加权求和」比「挑一个」好

- **可导**：softmax 权重可微，梯度能传回 encoder。
- **鲁棒**：即使某个权重算得不准，混合后仍有信息。
- **表达力**：权重可以是「0.6 看『我』+ 0.4 看『爱』」——**一个词可能同时依赖多个源词**（比如翻译「bank」可能同时看「河」和「钱」）。
- **挑一个**（hard attention）也存在，但需要强化学习训练，少用。

**soft attention（加权求和）是主流**，你后面看到的代码基本都是它。

## 再顺带：`hs` 是「所有步」，不是「最后一个」

- 普通 seq2seq：`C = hs[:, -1, :]`（只取最后一步）。
- Attention：`hs = 全部`（`(N, S, H)`），decoder 每步和**所有** `h_s` 算权重。

**这是 attention 能「不溢出」的根本——它保留了全部 `hs`，需要时去查。**
