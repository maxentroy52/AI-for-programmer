## 你的理解，确认

> 「训练完全可以一次喂一个词，只是效率不高。」

**对。** 数学上，两种做法**等价**：

**一次一个词：**

```python
for t in range(T):

```

**一次一个序列：**

```python
hs = TimeLSTM.forward(xs)      # 内部也是 for t，但封装了

loss.backward()                     # 一次回传整个序列
update()                            # 一次更新
```

**两者最终算出的梯度，数学上一样**（如果 lr 和更新策略一致）。区别在**工程效率**。

## 为什么「一次一个词」效率低

**1. 参数更新频繁，梯度噪声大**

一次一个词 → T 次更新，每次只基于 1 个位置的 loss。梯度**方差大、不稳定**。一次一个序列 → 1 次更新，基于 T 个位置的平均 loss，**梯度更稳**。

**2. BPTT 被切断**

一次一个词，每步算完就更新，**上一步的 cache 用完就丢**。但 BPTT 需要**倒序**用所有步的 cache 回传梯度。一次一个词**做不到完整的 BPTT**（除非你手动保留所有 cache，但那就等价于「攒着一起回传」= 一次一个序列了）。

**3. Python 循环 + 小矩阵**

T 次 Python 调用、T 次小矩阵乘法，比「一次大矩阵（batch 并行）」慢得多。

## 但有一个细微点：**「一次一个词」严格说不是「训练方式」，是「在线学习」**

如果你真的「每步更新」，那是 **online learning / SGD with batch=1（按时间步）**：

```
每个时间步 → 算 loss → backward → update
```

这在数学上**合法**，但：

- 梯度噪声大（每步只用一个位置）。
- BPTT 被截断成 1 步（看不到更早的历史）。
- 实践中很少用（除非流式场景）。

**标准做法是「攒一个序列（或一个截断块）的梯度，一起更新」**——这就是「一次喂一个序列」。

## 一句话

> **对，训练完全可以一次喂一个词，数学上等价，只是效率低。** 具体低在：参数更新频繁（梯度噪声大）、BPTT 被切断（看不到历史）、Python 循环 + 小矩阵慢。**「一次喂一个序列」不是「唯一正确」，而是「更高效、梯度更稳、BPTT 完整」的工程选择。** 一次一个词的极端版就是「在线学习」（每步更新），合法但少用。

## 顺带：为什么推理必须「一次一个词」

推理时**没有整个序列**——下一个词还没生成，你只有前面的词。所以：

```
生成第 1 个 → 喂回去 → 生成第 2 个 → ...
```

**训练时序列已知（`ts` 是现成的），可以一次喂整个。推理时序列未知，只能一次一个。** 这不是「效率选择」，是「信息约束」——**推理时你根本不知道后面的词**。

## 再顺带：teacher forcing 也是「一次喂一个序列」的体现

```python
xs = corpus[:-1]   # 输入: 整个前文序列
ts = corpus[1:]    # 标签: 整个下一个词序列
```

**一次喂整个 `xs`，一次算整个 `ts` 的 loss**——这就是「一次喂一个序列」+ teacher forcing。如果一次一个词，就是「每步喂 `xs[t]`，和 `ts[t]` 比」——**等价，但效率低**。
